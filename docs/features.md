# 핵심 기능 정의

> 한 줄 정체성: 공부하는 취업 준비생이 로그와 패킷을 보며 기초를 잡고, Wireshark로 빨리 넘어가게 돕는 학습용 분석 도구.

목표 느낌: "기초가 부족해 패킷 분석이 정신없었는데, 이 도구로 기초를 잡았다."

## 용어
- 디스플레이 필터: Wireshark에서 원하는 패킷만 보이게 거르는 조건식 (예: `tcp.port == 22`).
- tshark: Wireshark의 명령줄 버전.
- 재전송(retransmission): TCP가 상대가 못 받은 데이터를 다시 보내는 것. 네트워크가 느리거나 잠깐 끊겨도 생김.
- 규칙 파일: "이런 조건이면 이 경고를 띄운다"를 적어 둔 텍스트 파일(YAML).
- 타임라인: 시간 순서대로 사건을 나열한 화면.

## 대표 기능

### 1. 화면마다 붙는 도움 가이드
- 하는 일: 각 화면·열·필드 옆에 "?"를 두고, 누르면 한 줄 설명과 "여기서 무엇을 보면 되는지"를 보여 줌.
- 이유: UI/UX적으로 도움이 되는 가이드가 차별점 (답변 4).
- 예시 화면:
  ```
  [?] Flags: SYN
  TCP 연결을 처음 시작할 때 보내는 신호입니다.
  여기서 볼 것: 한 IP가 짧은 시간에 여러 포트로 SYN만 보내면 포트 스캔일 수 있습니다.
  ```

### 2. Wireshark 명령 같이 보기 (가장 중요)
- 하는 일: 사용자가 클릭으로 거르거나 볼 때마다, 같은 일을 하는 Wireshark 디스플레이 필터와 tshark 명령을 옆에 보여 주고 복사 버튼 제공.
- 이유: 보면서 명령을 자연스럽게 외우고 Wireshark에 빨리 적응 (답변 10, 16).
- 예시 화면:
  ```
  지금 보는 것: 192.168.0.10 과 주고받은 SSH 패킷
  Wireshark에서는: ip.addr == 192.168.0.10 && tcp.port == 22
  tshark로는:      tshark -r sample.pcap -Y "ip.addr == 192.168.0.10 && tcp.port == 22"
  [복사]
  ```

### 3. 로그 섹션 / 패킷 섹션 분리 + 시간 연결
- 하는 일: 로그와 패킷을 다른 탭에 따로 보여 주고, 한쪽에서 한 줄을 고르면 다른 쪽에서 같은 시간대(앞뒤 몇 초)를 강조.
- 이유: 섹션은 따로, 기준은 시간 (답변 5).
- 예시 화면:
  ```
  [로그] 10:02:15 auth.log  Failed password for root from 203.0.113.5
  → [패킷] 10:02:14~10:02:16 사이 203.0.113.5 패킷 12개 강조됨
  ```

### 4. 이유·근거·다음 단계가 있는 경고 카드
- 하는 일: 규칙에 걸리면 카드 하나로 보여 줌. 항상 원본 줄/패킷(근거)을 같이 표시.
- 이유: 왜 이상한지 → 다음 확인 단계까지 (답변 6), 근거는 항상 보여 줌 (답변 14), 규칙 기반만 (답변 15).
- 예시 화면:
  ```
  ⚠ 같은 IP의 SSH 로그인 실패 반복
  왜 이상한가: 203.0.113.5 에서 1분 안에 비밀번호 실패가 8번 있었습니다. 비밀번호를 하나씩 맞춰 보는 공격(무차별 대입)일 수 있습니다.
  근거: auth.log 23~30번째 줄 [원본 보기]
  다음 확인 단계:
    1. 같은 IP로 성공한 로그인(Accepted)이 있는지 보기
    2. 패킷 섹션에서 이 시간대 22번 포트 연결 수 보기
  Wireshark에서는: ip.src == 203.0.113.5 && tcp.dstport == 22
  ```

### 5. 초보 오해 미리 잡기
- 하는 일: 초보가 공격으로 착각하기 쉬운 정상 현상을 만나면 "오해 주의" 힌트를 띄움.
- 이유: 초보가 틀리기 쉬운 해석을 미리 잡기 (답변 7).
- 예시 화면:
  ```
  💡 오해 주의: TCP 재전송
  재전송이 보인다고 공격은 아닙니다. 네트워크가 느리거나 잠깐 끊겨도 생깁니다.
  같이 볼 것: 특정 IP 하나에 몰려 있는지, 시간대가 짧은지.
  Wireshark에서는: tcp.analysis.retransmission
  ```

### 6. 공부 노트 요약 (선택 기능)
- 하는 일: 버튼을 누르면 이번 분석에서 본 경고, 쓴 필터, 배운 용어를 마크다운 노트로 내보냄. 포트폴리오에 붙일 수 있음.
- 이유: 선택 기능 (답변 8), 포트폴리오 (답변 16, 17).
- 예시 화면:
  ```
  ## 오늘의 분석 노트 (sample.pcap, auth.log)
  - 찾은 것: SSH 무차별 대입 의심 1건
  - 쓴 필터: ip.src == 203.0.113.5 && tcp.dstport == 22
  - 배운 용어: SYN, 재전송
  ```

## 하지 않는 것 (비목표)
- 실시간 캡처, 자동 차단, 대용량(수백 MB 이상) 처리
- AI 설명 (규칙 기반만)
- 실무 고급 기능 (SIEM 연동, 경보 자동화, 사용자 계정 관리)
- 지원 로그 외 형식 (처음에는 auth.log, access.log, Windows 이벤트 로그만)

## 추가 기능 (Zeek 분석 반영, [analysis/zeek.md](analysis/zeek.md))

### 7. 대화(연결) 요약 탭
- 하는 일: 패킷을 연결 단위로 묶어 한 줄씩 보여 줌(Zeek conn.log 방식). 각 대화에 uid를 붙이고, 상태를 쉬운 한국어로 풀어 줌. 한 줄을 누르면 패킷 탭에서 그 대화의 패킷만 강조.
- 이유: 기초가 부족하면 패킷 하나하나가 정신없음 (답변 3). 대화를 먼저 보고 패킷으로 내려가게 함.
- 예시 화면:
  ```
  대화 C1  192.168.4.76:46378 → 31.3.245.133:80 (HTTP)  0.25초  보냄 77B / 받음 295B
  상태: 정상 연결·정상 종료 (SF)
  흐름: S h A D a d F f → 연결 시작(SYN) → 응답(SYN-ACK) → 확인(ACK) → 데이터 주고받음 → 양쪽 종료(FIN)
  Wireshark에서는: tcp.stream eq 0
  ```

### 8. 열 고르기 + 같은 명령 보기
- 하는 일: 로그·패킷·대화 탭에서 보고 싶은 열을 체크박스로 고름. 시간 열은 읽기 쉬운 현지 시간(Asia/Seoul 등 설정)으로 바꿔 보여 줌. 고른 열만 CSV(쉼표로 구분한 표 파일)로 내보내기. 고를 때마다 같은 일을 하는 명령을 옆에 보여 줌.
- 이유: 명령을 보면서 자연스럽게 외우기 (답변 10), Wireshark·실무 도구에 빨리 적응 (답변 16). zeek-cut, tshark `-T fields`가 하는 "원하는 칸만 뽑기"를 화면으로 먼저 익힘.
- 예시 화면 (패킷 탭에서 시간, 출발지, 목적지, 목적지 포트 선택):
  ```
  ☑ 시간  ☑ 출발지 IP  ☑ 목적지 IP  ☐ 프로토콜  ☑ 목적지 포트     [CSV로 내보내기]
  tshark로는:   tshark -r sample.pcap -T fields -e frame.time -e ip.src -e ip.dst -e tcp.dstport -E header=y -E separator=,
  ```
  대화 탭 (Zeek conn.log를 읽었을 때):
  ```
  zeek-cut으로는: cat conn.log | zeek-cut -d ts id.orig_h id.resp_h id.resp_p
  ```
  로그 탭 (access.log, 기본 combined 형식):
  ```
  awk로는: awk '{print $1, $4, $9}' access.log      # IP, 시간, 상태 코드
  ```
- 주의 문구: awk의 칸 번호는 로그 형식에 따라 다를 수 있음 (특히 auth.log). 화면에 "형식이 다르면 칸 번호가 바뀝니다"를 같이 표시.

## 추가 반영 (Suricata 분석, [analysis/suricata.md](analysis/suricata.md))

### 경고 카드에 "Suricata 룰로 쓰면" 보기 (학습용, 읽기 전용)
- 하는 일: 경고 카드 아래에 같은 뜻의 Suricata 룰 예시를 보여 주고 각 칸(msg, sid, threshold 등)을 한 줄로 설명. 우리 도구는 이 룰을 실행하지 않음.
- 이유: 명령과 형식을 보면서 외우기 (답변 10), 실무 도구 적응 (답변 16).
- 예시 화면:
  ```
  ⚠ 짧은 시간에 여러 포트 접속 (포트 스캔 의심)   [분류: 정찰 시도]  [규칙 R-002 v1]
  왜 이상한가: 203.0.113.5 가 60초 안에 서로 다른 포트 12개에 연결을 시도했습니다.
  근거: 패킷 #15, #16, #18 ... [원본 보기]
  다음 확인 단계: 1) 응답(SYN-ACK)이 온 포트가 있는지  2) 같은 IP의 로그 기록
  Wireshark에서는: ip.src == 203.0.113.5 && tcp.flags.syn == 1 && tcp.flags.ack == 0
  Suricata 룰로 쓰면 (참고용):
    alert tcp any any -> $HOME_NET any (msg:"포트 스캔 의심"; flags:S; detection_filter: track by_src, count 10, seconds 60, unique_on dst_port; classtype:attempted-recon; sid:1000002; rev:1;)
  ```

## 추가 반영 (Sigma·Wazuh 분석, [analysis/log-tools.md](analysis/log-tools.md))

### 경고 카드에 중요도·오해 주의·신뢰도 표시 (4번 기능 보강)
- 하는 일: 경고 카드 맨 위에 `level`(높음/중간/낮음)과 신뢰도(`근거 충분` / `더 확인 필요`)를 보여 줌. 아래에 `오해 주의`(문제가 아닐 수 있는 경우)를 적음.
- 이유: 근거는 항상 보여 줌 (답변 14). 초보가 경고를 곧바로 "공격"으로 믿지 않게 함 (5번 기능과 같은 목적).
- 예시 화면:
  ```
  ⚠ 같은 IP의 SSH 로그인 실패 반복   [level: 중간]  [근거 충분]
  ...
  오해 주의: 비밀번호를 잊은 사용자가 여러 번 틀려도 같은 경고가 납니다.
  ```
- 설계 위치: [design.md](design.md) 7단계. 로그를 필드로 나누는 정규식 표(`decoders.yaml`)는 1단계.
